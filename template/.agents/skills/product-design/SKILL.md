# Product Design Review

Start with the user's primary job, frequency, context and constraints. Make the primary action easiest to understand and perform; avoid designing from entities or internal implementation language.

Review information architecture and domain terminology, hierarchy, interaction cost, density, spacing, alignment, typography, existing components/tokens, responsive/touch behaviour, semantic HTML, keyboard/focus, contrast, empty/loading/validation/error/success/disabled states, destructive safeguards and perceived responsiveness.

Prefer clarity over novelty, progressive disclosure over option overload and coherent existing patterns over one-off UI. Improve small low-risk rough edges in the changed flow, but do not turn a focused ticket into a redesign project. Treat labels/copy as part of design.

For significant visual changes inspect the rendered result when tooling permits and validate the real target devices/widths. Return only findings that materially improve the product.
